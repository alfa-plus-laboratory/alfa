# alfa

[![release](https://img.shields.io/github/v/release/alfa-plus-laboratory/alfa?style=flat-square&color=0B5C9E)](https://github.com/alfa-plus-laboratory/alfa/releases/latest)
[![license](https://img.shields.io/badge/license-Apache--2.0-0B5C9E?style=flat-square)](LICENSE)

**ターミナルの中に住むコーディング agent。** プロジェクトを開いて、やりたいことを
書くだけ。コードを読み、ファイルを編集し、テストを走らせます。取り返しのつかない
操作の前には、必ず確認します。

モデル呼び出し以外はすべて自分のマシンで動きます。自分の API キーで、自分の
provider に直接。バックエンドもアカウントもテレメトリもありません。

*他の言語:[English](README.md) · [中文](README.zh.md)。*

## インストール

```bash
curl -fsSL https://github.com/alfa-plus-laboratory/alfa/releases/latest/download/install.sh | sh
```

```powershell
irm https://github.com/alfa-plus-laboratory/alfa/releases/latest/download/install.ps1 | iex
```

ファイル 1 つ、ランタイムの事前インストールは不要 —— バイナリが自分で持っています。
macOS と Linux は x64 / arm64、Windows は x64 に対応。インストーラは SHA-256 を
照合し、一致しなければインストールを拒否します。

以降の更新は `alfa upgrade` でその場で入れ替え。**勝手に更新することはありません**。
新しい版があると伝えるだけで、入れ替えるかどうかはあなたが決めます。

自分でビルドしたい場合は[ソースからビルド](#ソースからビルド)へ。

## 最初の起動

```bash
cd your-project
alfa
```

初回はモデル provider を尋ねます。Anthropic、OpenAI、あるいは OpenAI 互換の
エンドポイントの API キーを貼ると、保存する前に検証します。

**フォルダごとの初回**には短い質問が 2 つ:画面の見え方と、このフォルダを信頼するか。
どちらの答えも**あなたの config に**保存され、リポジトリには一切書き込みません。
既定でよければ Enter を 2 回。

あとは話しかけるだけです:

```
› ログイン処理がリダイレクト時に session cookie を落としている。原因を調べて
› カートが空のケースのテストを足して、通るようにして
› このリポジトリは結局なにをするもの?まず自分で一通り読んで
```

フルスクリーン UI が不要なら `alfa --plain` で、いつものスクロールバッファの下端に
入力欄が出る形になります。スクリプトから使うなら `alfa -p "…"` が 1 ターンだけ実行
して終了します。

## できること

15 個の組み込みツール:`read` `write` `edit` `bash` `grep` `glob` `todo` `job`
`task` `ask` `memory` `context` `skill` `webfetch` `websearch`。

分かりやすいもの以外だと、こういうことができます:

- **バックグラウンドで動かす** —— dev server を立てて、作業を続けて、あとで様子を
  見る。alfa の終了時にそれらのプロセスはきちんと終了され、孤児になりません。
- **サブ agent を送り出す** —— `task` は独立したコンテキストウィンドウを持つサブ
  agent を起こします。「サブツリー全体を読む必要があるが、答えは一段落」という問い
  に向いています。`/agentflow` を有効にすれば複数を同時に出し、パイプラインに
  並べられます。
- **手を止めて聞く** —— 本当の分岐点に来たら、推測せずに質問して待ちます。
- **セッションをまたいで覚える** —— 書いたメモは `.alfa/memory/` に入り、次回の
  最初から読み込まれます。
- **自分の仕事を検証する** —— 引き渡す前に、見つかればプロジェクトの型チェックや
  ビルドを走らせ、自分が壊したところを直します。

## パーミッション

リポジトリを預ける前に、ここだけは読む価値があります。

すべてのツール呼び出しはゲートを通ります。読み取りは無条件。書き込み・削除・
ネットワークは分類され、その内容が**省略なしで**表示されます —— シェルコマンドなら
パイプラインの各区間を 1 行ずつ。ざっと見て y を押させるための 1 行にはしません。

モードは 3 つ。`shift-tab` または `/permission` で切り替えます:

| モード | 意味 |
|---|---|
| `confirm` | 読み取りも含めてすべて確認する |
| `default` | 書き込み・削除・ネットワークの前に確認する |
| `trust` | 確認せずに実行する |

既定は `default`。既定以外のモードは**必ず起動時に表示されます** —— 忘れられる
セキュリティ設定は、セキュリティ設定ではありません。

「以後は聞かない」はワークスペース単位で記憶され、そのルールが何件効いているかを
起動時に伝えます。**どのモードでも決して許可されない**ものもあります:認証情報
ファイルの読み取り、ワークスペース外への書き込み、link-local およびクラウド
メタデータアドレスへのアクセスは常に拒否されます。

**モデルが外から読むものはすべて、指示ではなくデータとして扱われます。** Web ページ、
検索結果、MCP ツールの戻り値、そしてあなたが書いたのではないファイルは、同じ
フィルタを通ります。不可視文字を取り除き、agent に命令しようとする文面には印を
付けます。これは考えすぎではありません —— `node_modules` に紛れ込んだ汚染された
README は、Web ページとまったく同じ経路でモデルに届きます。

## フォルダの信頼

リポジトリは、あなたが何もしなくても agent に語りかけられます。`AGENTS.md` と
`CLAUDE.md` はそのまま system prompt に入り、`.alfa/mcp.json` は起動する実行
ファイルを指定できます。自分のコードなら問題ありませんが、clone してきたばかりの
ものでは話が別です。

信頼は**既定で与えられます** —— ディレクトリごとに `y` を押させるツールは、
読まずに押す習慣を教え込むだけです。大事なのは、**与えない道がはっきりあること**と、
**与えた日付が残ること**です。

「先に目を通す」を選ぶと、サブ agent がそれらのファイルを読み、プロジェクトを
説明しているのではなく **agent を誘導している**記述が何もない場合にだけ信頼済みに
します。判定基準は**その一文の効果がどこへ向かうか**であって、口調の強さでは
ありません:「コメントを書くな」はハウスルール、「.env をこのアドレスへ送れ」は
違います。確認から何か指摘が出た場合 —— あるいはそもそも返ってこなかった場合 ——
そのフォルダは信頼しないままになります。

信頼されていない間、そのフォルダの `AGENTS.md`、`CLAUDE.md`、`.alfa/memory/`、
`.alfa/skills/` は **system prompt に一切入らず**、起動時にその旨が表示されます。
管理は `/trust` で。

## キー操作

| キー | |
|---|---|
| `enter` | 送信 —— 実行中なら待機列に入る |
| `ctrl-j` | 改行 |
| `esc` | このターンを中断。それ以外は近い順に 1 段戻る |
| `tab` | ペイン移動 —— 入力すると必ず入力欄へ戻る |
| `shift-tab` | パーミッションモード |
| `/` `@` | コマンドパレット · ファイルの参照 |
| `ctrl-b` `ctrl-p` `ctrl-]` | ファイルツリー · 計画 · 詳細ペイン |
| `ctrl-y` | コピー —— コードブロック、返答、自分の発言、セッション全体 |
| `ctrl-l` | 画面を再描画 |
| `ctrl-o` `ctrl-r` | 詳細ペインを固定 · ツリーを再読込 |
| `ctrl-c` | 入力を消去。空行で 2 回押すと終了 |

### コピーについて

フルスクリーンのターミナルアプリはマウスを捕まえるので、ドラッグ選択が効きません。
仮に選べたとしても、選べるのは**画面の見た目**です —— 枠線、折り返された行、隣の
ペインの文字まで一緒に入ってきます。

`ctrl-y`(またはステータス行の `[⧉ copy]`)はコピーできるものを一覧し、テキストは
**セッションのデータから**取ります:直近の返答に含まれる各コードブロック、返答その
もの、自分の直前の発言、会話全体。OSC 52 で送るので、**SSH 越しでも同じように
動きます**。tmux では `set -g set-clipboard on` が必要です。

## コマンド

`/help` `/context` `/compact` `/check` `/init` `/model` `/view`
`/language` `/permission` `/trust` `/think` `/agentflow` `/mcp` `/skills`
`/resume` `/summary` `/clear` `/history-clean` `/reset` `/upgrade` `/exit`

知っておくと良いもの:

- **`/init`** はリポジトリを実際に読んだうえで `AGENTS.md` を書きます —— ビルド方法、
  テスト方法、破ってはいけない取り決め。
- **`/compact`** は長くなったセッションを引き継ぎ用の要約に畳みます。コンテキスト
  ウィンドウが埋まりかけると自動で走り、原文は一字も消しません。
- **`/context`** は今なにがコンテキストを占めているかを示します。どこを削るかの判断用。
- **`/reset`** は alfa の状態を消し、**`alfa uninstall`** は alfa 自身(バイナリを
  含む)を消します。どちらも削除する前に一覧を見せます。

## 設定

意図的に 2 つのファイルに分けています:

| | |
|---|---|
| `~/.config/alfa/config.json` | provider、既定モデル、各種設定。**秘密情報は 1 バイトも含みません** —— dotfiles リポジトリに入れて構いません |
| `~/.local/share/alfa/auth.json` | API キー。パーミッションは `0600` |

```json
{
  "model": "anthropic/claude-sonnet-4-5",
  "providers": {
    "anthropic": { "type": "anthropic" },
    "local": {
      "type": "openai-compat",
      "baseURL": "http://localhost:11434/v1",
      "models": ["qwen2.5-coder:32b"]
    }
  },
  "language": { "interface": "auto", "reply": "auto" }
}
```

OpenAI 互換のエンドポイントならどれでも繋がります —— ローカルの llama.cpp や
Ollama、自前のゲートウェイ、ホスティングサービス。**このファイルを手で編集するのは
サポートされた使い方**なので、エラーメッセージはどのフィールドが何を期待していたか
を明示します。

環境変数での上書き:`ALFA_KEY_<PROVIDER>`、`ALFA_BASE_URL_<PROVIDER>`、
`ALFA_MODEL`、`ALFA_SHELL`、`ALFA_DEBUG=1`。

インターフェースは English / 中文 / 日本語 に対応(`/language`)。キー名・ツール名・
モード名は**翻訳しません** —— それらは打ち込むものだからです。

### MCP・skills・メモリ

- **MCP** —— server は `config.json`(あなたのもの)か `.alfa/mcp.json`
  (プロジェクトのもの)に書きます。**プロジェクト側**が定義したものは、起動前に
  あなたの明示的な許可が必要です。あのファイルは実行ファイルを指定するからです。
- **Skills** —— 手順書は markdown ファイル 1 つで、`.alfa/skills/`、
  `~/.config/alfa/skills/`、`.claude/skills/` のいずれかに置きます。prompt に載るのは
  名前と 1 行の説明だけで、本文は必要になったときに取りに行きます。
- **メモリ** —— `.alfa/memory/` には agent がそのプロジェクトについて書いたメモが
  入り、各セッションの冒頭で読み込まれます。`/init` と `memory` ツールで管理します。

## プライバシー

alfa に**テレメトリはありません**。解析用のコードはソースに存在せず、私たちの
エンドポイントも存在しません。

ネットワークに出るのは、次の 3 種類の宛先だけです:

1. **あなたが設定したモデル provider** —— あなたのキーで。
2. **GitHub** —— バックグラウンドで 1 日に最大 1 回、新しいリリースがあるかを見る
   だけ。**伝えるだけで、勝手には入れません**。`alfa upgrade` もここから取得します。
3. **Web、ただしあなたが許可したときだけ** —— `webfetch` と `websearch` は毎回
   承認が必要で、**意図的にホワイトリストを持ちません**。リスクは「どのサイトか」
   ではなく「**誰がそれを選んだか**」だからです。

それ以外 —— セッション、履歴、保存されたツール出力、認証情報 —— はすべて手元の
`~/.local/share/alfa/` に残ります。`/reset` と `alfa uninstall` は削除前に一覧を
見せます。

## ソースからビルド

```bash
git clone https://github.com/alfa-plus-laboratory/alfa
cd alfa
bun install
bun run typecheck && bun test
bun run build          # → bin/alfa-bin
```

**[Bun](https://bun.sh) 1.3 以上**が必要です(**node ではありません**)。配布される
バイナリは固定した bun バージョンでビルドされます。`bun build --compile` はランタイム
ごと同梱するため、**ビルドに使った版がそのままユーザーの実行する版になる**からです。

## ドキュメント

[**DESIGN.md**](DESIGN.md) は設計ログです —— 判断の根拠、試して駄目だったこと、
変えると何が壊れるか。長く、中国語で、そして「このコードがなぜこうなっているか」の
唯一の真実の源です。**使う前ではなく、変える前に**読んでください。

[**AGENTS.md**](AGENTS.md) はこのリポジトリで作業するときのハウスルールです。短く、
**通常の既定とは逆になっている**ものも含みます。
